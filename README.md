# 會議室預約看板

純前端的會議室預約工具：以日視圖時間軸呈現各會議室的預約狀況，可新增、取消預約，並自動攔截時段衝突。不需後端、不需建置，用瀏覽器開啟即可使用。

> 需求細節請見 [spec.md](spec.md)，其第 6 節驗收標準為驗證依據。

## 功能清單

- **日視圖時間軸**：依日期顯示每間會議室的預約，手機寬度（約 375px）時時間軸可橫向捲動
- **新增預約**：會議室、日期、開始／結束時間、會議主題、預約人姓名皆必填；主題與姓名不可純空白；結束時間須晚於開始時間
- **衝突檢查**：同一會議室同一天內，相同、部分重疊、包含的時段一律拒絕並顯示錯誤；首尾相接（如 10:00–11:00 與 11:00–12:00）允許；不同會議室可同時段
- **取消預約**：刪除前需二次確認；不支援修改（請刪除後重建）
- **資料保存**：存於瀏覽器 `localStorage`，重新整理後仍在
- **匯出 CSV**：匯出全部預約（日期、會議室、開始／結束時間、主題、預約人），不含匯入

### 已知限制

- 資料只存在各自瀏覽器，**不同人員／瀏覽器之間不互通**，無法跨人防撞時段
- 時間以本機時區為準；無登入機制
- 刻意不做：權限、週期性預約、設備／容納人數篩選、通知／行事曆整合、多人即時同步、大螢幕模式

## 如何開啟使用

1. 取得專案（`git clone` 或下載資料夾）
2. 直接以瀏覽器開啟 `index.html`（雙擊即可）

不需安裝套件、不需啟動伺服器。

### 設定

會議室清單、可預約時段與時間單位集中在 [index.html](index.html) 的常數區（約第 183 行起），直接修改即可：

| 常數 | 預設值 | 說明 |
| --- | --- | --- |
| `ROOMS` | A／B／C 會議室 | 會議室清單（建議 3～5 間） |
| `DAY_START` / `DAY_END` | `8` / `18` | 可預約時段（24 小時制） |
| `SLOT_MIN` | `30` | 時間單位（分鐘） |
| `STORAGE_KEY` | `room-bookings-v1` | localStorage 的鍵名 |

## 如何執行測試

本專案沒有測試框架或指令，測試為一個獨立頁面：

1. 用瀏覽器開啟 `test.html`
2. 頁面頂端顯示「通過 N 項／共 N 項」（綠色＝全數通過，紅色＝有失敗），下方表格列出每個案例的預期值、實際值與結果

目前涵蓋 `findOverlap` 的 11 個案例：完全相同、完全錯開、前段／後段部分重疊、互相包含、首尾相接（前後）、不同會議室、不同日期、多筆預約中僅一筆衝突。

> 表單驗證與時間軸畫面等其餘功能，請依 [spec.md](spec.md) 第 6 節驗收標準手動操作 `index.html` 驗證。

## 檔案結構

```
room/
├── index.html   主程式：介面、樣式、設定常數、時間軸繪製、表單驗證、localStorage、匯出 CSV
├── app.js       衝突判斷函式 findOverlap（供 index.html 與 test.html 共用）
├── test.html    findOverlap 的瀏覽器測試頁
├── spec.md      需求規格（繁體中文）
├── bugs.md      點交紀錄
└── CLAUDE.md    給 AI 協作工具的專案指引
```

`app.js` 以一般 `<script>` 載入，依賴全域的 `bookings` 與 `toMinutes`：`index.html` 內有正式定義，`test.html` 則提供測試用版本。

## 開發規範

- 程式維持 `index.html`＋`app.js`＋`test.html` 三檔，不再拆分，不引入外部框架
- 介面文字與程式註解一律使用繁體中文
- 修改衝突判斷邏輯時，請先在 `test.html` 補上對應案例
